# Digital job file — specification by division

What the paper file contains today, field by field, so it can be rebuilt inside the dashboard.

**Source column:**

| Mark | Meaning |
|---|---|
| **Z** | Read from Zoho. Never typed. |
| **E** | Entered by a person. |
| **D** | Derived by the system. Never typed, never stored as input. |

### 1.3 Job document reference sheet

Five sections, eight rows each, filled by **three different people at three different times**.

| Section | Filled by | When |
|---|---|---|
| Assemblies | Coordinator | On file return from production |
| Picklists | Coordinator | On file return |
| Inventory adjustments | Coordinator | On file return |
| Shipments | **Ilham (Stores)** | On dispatch |
| Internal transfer notes (ITN) | **Darshani** | On invoice |

Each row: reference no (**E**, or **Z** if auto-matched), date (**D** from entry), generated by (**D** from logged-in user), line manager approval (**E**).

Currently filled retrospectively from the production report, which is why no real event timestamps exist today. **In the digital version these must be captured live.**

Printed note on the sheet: all documents listed here exist in the electronic system; printouts are for audit only. The dashboard enforces existing policy, it does not introduce new policy.

### 2.3 QC visual verification & approval checklist (QMS controlled)

Customised orders only. Ten checkpoints, each yes/no/NA plus remarks:

customer visual received and confirmed · design team artwork received · layout matches customer visual exactly · text content and spelling verified · font style and size match · pantone code mentioned · logos and brand elements correct · barcode placement and size verified · die line/cut line alignment verified · customer special instructions followed

Plus: QC status (approved for platemaking / rejected — corrections required), remarks, designer name + signature + date, QC reviewer/approver name + signature + date. All **E**.

Customer, item, date, print colour (**Z** where possible), plus the artwork image itself (file upload).

## Part 7 — Build notes

### 7.1 Screen structure

One job page with tabs matching the paper file:

```
Overview  |  Checklist  |  Production  |  Reference sheet  |  QC  |  Documents
```

- **Overview** — the Zoho sales order, read-only
- **Checklist** — the 11 stages, 7 auto-ticked by sync, 4 tapped
- **Production** — inline inspection rows + the division's labour record
- **Reference sheet** — five sections, each visible only to whoever owns it
- **QC** — controlled documents, append-only
- **Documents** — artwork, proofs, photos

### 7.2 Field rules

- **Nothing typed that Zoho already has.** Every Z field is display-only.
- **Every timestamp is D.** Taken from the action, never a date picker.
- **Every "generated by" is D.** Taken from the logged-in user.
- Job numbers are **opaque strings**. Never parsed. Formats vary wildly: `OPD6700`, `PSU/BTN/989`, `RWU/IMP2357/QPP/00025/BIO`.
- Repeating sections (inline inspection rows, interval rows, dispatch references) need add-row, not fixed slots.
- Reference numbers should **auto-match against synced Zoho documents** where possible, and fall back to manual entry.

### 7.3 Two fields that exist nowhere today

- **Order received date** — when the WhatsApp message arrived. Without it there is no true start of the 14 days.
- **Handover timestamps** — file out to production, file back to coordinator, to Ilham, to Darshani. These give both file location and dwell time.

### 7.4 What stays on paper for now

Nothing forces itself out. But the two QMS-controlled checklists carry doc numbers, revisions and signatures. Either build them properly with an append-only approval record, or leave them on paper until the rest is stable. Do not fold them into a generic stage tick.

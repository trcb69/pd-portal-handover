The three decisions, in detail

1. Read-only Zoho access for SmartPack — an admin action, not a discussion

A "Self Client" in Zoho's API console: credentials that let the dashboard read SmartPack's sales orders and assemblies every few minutes, and never write anything back. Full steps are written out at dev/production-dashboard/docs/zoho-self-client-setup.md.

  • Watch one thing: at the last step Zoho asks which company - pick SmartPack. Picking Standard Holdings is the usual mistake and the system would then read the wrong company's orders.
  • The secret goes straight into the server file. Never into a chat, a report or an email.
  • Second half, a lookup in Zoho settings: what is the real daily API call limit on SmartPack's plan? We have been planning against 1,000 a day and that figure is unverified. Three things will share it. If the real number is lower, I size the system down now rather than after it breaks.

What it unblocks: twelve read-only checks that settle four settings which are guesses today - including one that, if wrong, would stop every job loading on the first day.

2. Which field decides a job's division

Zoho stores the division twice: once on the order, once on each item line. On a full year of orders they disagree far more than anyone expected.

  • My recommendation: the item line tag decides; the order field is used only when the line has no tag; and where the two disagree the job is marked so somebody can fix Zoho.
  • Why: the order field is a bucket, not a division. Of 2,029 lines whose order says "Offset Printing Division", the line tags say PackPro 1,451, MacPro 462, MOBA 93.
  • And: 333 lines carry no tag at all - 215 of Rewinding's 224 - so the order field has to stay as the fallback. It cannot simply be replaced.

3. How the screen decides its data is trustworthy — my recommendation: change it

Today's design: every night at 2am the system re-reads the entire order list, and that nightly run is what tells the screen its data is good.

The problem: if that one run fails - Zoho rate-limits us, a token expires, the connection drops - nothing retries it. Two failed nights and every manager's screen goes blank: no counters, no flags, just a grey banner, and nobody can fix it at 2am.

What I recommend: judge freshness from the small continuous updates instead, and run the full sweep weekly, only to catch deleted orders. If the weekly sweep is overdue, that shows on my admin screen - never as a blank screen for a manager.

  • Gains: removes one of the design's worst failure modes, and frees about 43 Zoho calls a day - turning a daily budget that currently lands exactly on the limit into one with room.
  • Costs: one kind of quantity refresh happens continuously instead of nightly. The design already prevents that from raising a false alarm.
  • This is a technical call, not a business one. It needs your yes or no, not the managers'.

Questions for the managers

What to ask each manager, to release the dashboard

These are the answers that change what gets built. Everything else can be adjusted in settings afterwards.

Ishan — PackPro, Paper Straw, Rewinding (and MacPro?)

  1. PackPro and MacPro - what is the difference, and who runs MacPro? Both are tagged "OPD - ..." and both make Taco Bell wraps and kraft boxes. The same item appears under both tags in the same year. This is the single biggest unknown.
  2. Rewinding: 215 of 224 order lines carry no division tag at all. Is the tag simply not used for cling film work? Those jobs can only be routed by the order field.
  3. Paper Straw: 88 of 305 lines also have no tag. Does that matter to you?
  4. Straw has only 7 different items and every order is for Standard Holdings - is it effectively made to stock rather than to order? It changes what "late" means on the screen.

Mubeena — Screen Printing

  1. Your division is the cleanest data in the company - 1,078 of 1,080 lines tagged correctly, not one disagreement. Whatever is being done here, I would like the others to copy it. What is it?
  2. At what point in your day do you know a screen or plate is ready? That is the thing the dashboard should show you first, and it is not recorded anywhere today.
  3. 560 different items across 950 orders - does a repeat customer get a new item code each time?
  4. When a print job has to be redone, how does that show up in Zoho today?
  5. What would make you open this screen every morning rather than use it because IT asked?

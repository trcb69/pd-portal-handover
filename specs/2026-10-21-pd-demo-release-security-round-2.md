- **S19 MED** Out-of-band runs the wrong way: admin verifies in person or calls back a number on record; name where the number lives (directory or `users.phone`); same for recovery codes.
- **S20 MED** Code submission: same body/status for wrong, expired, cancelled, locked, never-issued, unknown email; unknown emails write the same row (user_id NULL); waiting/status never show name or role.
- **S21 MED** Status endpoint: GET, pass-cookie only, `{status}` + match code while pending, same 401 without pass, ≤ 30/min per pass and IP, never reveals approver or name. Match code = HMAC(server key, pass), unambiguous alphabet, 6 chars; wrong entries audited, 3 → row cancelled; AC approving expired/replaced/blocked → refused.
- **S22 MED** Codes bound to purpose and binding (enrol → pre-auth cookie; step_up → session; fingerprint → browser); step-up mail names the action; AC cross-purpose refusal.

# Security review (design) of the website sign-in — PD demo release Rev 2, 21 Oct 2026

Saved by the lead from the security-auditor's hand-back. **VERDICT: PASS-WITH-CHANGES.** S1–S12 must be in the
spec and ACs before build step 2; S1–S6 decide account takeover.

- **S1 HIGH** Mistaken approval: match code (6 chars from the credential) shown on the waiting screen, typed by the admin from an in-person/known-phone readout; admin-set labels; approval row shows server-seen facts (time, IP, office network y/n, UA browser/OS, AAGUID hint, synced/device-bound); pending expires 24 h; max 1 pending per user (new one replaces + warns); email on enrol and approve; optional office-IP-only enrolment unless admin opens a 30-min window.
- **S2 HIGH** No self-approval; admin-role devices approved only from a tunnel session or by a second admin; first admin passkey bootstrapped via tunnel; ACs.
- **S3 HIGH** Tunnel = `req.socket.localAddress === '127.0.0.1'` AND loopback remote AND no X-Forwarded-For/Forwarded/X-Real-IP; never Host. Bridge listener always public. Sessions bound to path (password sessions only on loopback listener, device sessions only on bridge), checked in loadSession/requireAuth. Password login requires admin role. AC-D13 reworded with spoofed Host/forwarded tests. `requireOrigin` (`middleware.js:21-26`) must accept the tunnel origin only on the loopback listener.
- **S4 HIGH** Only two ways to create a session: passkey assertion on an active device (sets device_id) or password on the tunnel. Zoho exchange route absent; EXTENSION_ORIGINS empty, startup refuses otherwise (`middleware.js:57-63`); test enumerates session-creating routes.
- **S5 HIGH** Synced passkeys: store backup flags, show "synced", decide policy; rewrite §4.1. Cookie theft: device sessions ~14 h absolute / ~4 h idle (today 7 d / 12 h, `sessions.js:3-4`); loadSession joins user_devices each request (active device + active user); optional UA pin.
- **S6 HIGH** WebAuthn params as ACs: rpID = exact host (startup check vs APP_ORIGIN); expectedOrigin = APP_ORIGIN; refuse crossOrigin/topOrigin; userVerification required (checked both ceremonies); residentKey required + empty allowCredentials; server-stored single-use 5-min challenges on a `__Host-` pre-auth cookie; random opaque user.id; userHandle match; attestation none; sign-count 0 allowed; registration only with a single-use 10-min enrolment ticket from a correct code; excludeCredentials.
- **S7 MED** Atomic try counting (`UPDATE … tries < 5 …` row-count check) + parallel test; code bound to pre-auth cookie; new code cancels old; constant-time compare; HMAC with server secret; send to stored email; caps: 10 wrong/24 h per email (DB-counted) then lock + alert, ~10 req/h per IP, ~30 mails/h global; identical wrong/expired/unknown answers, unknown emails also "lock"; queue mail, answer at once; code in body not subject, browser + time, "IT will never ask".
- **S8 MED** Block person also stops codes/enrolment (define = users.active=0 or new flag), cancels codes, tickets, pending devices; SSE closeSession/closeDevice (`services/sse.js:13`); blocked device permanent; changing zoho_email blocks all devices (`admin-users.js:115-118`).
- **S9 MED** Admin recovery code: one named user, single use, 30 min, hashed, same limits; given in person or via a number on record; device still pending + S1 match code; audit who/for whom, never the code; ACs.
- **S10 MED** Step-up: admin approve/block/recovery/email or role change from the public site needs a passkey assertion ≤ 5 min old.
- **S11 MED** Pending device gets no session (status polled with the enrolment ticket); or allow-list + AC walking every /api route → 403.
- **S12 LOW–MED** AC: no codes/challenges/tickets/tokens/SMTP password in logs or audit_log.detail_json; nodemailer logger/debug off, TLS required + cert verified; error handler (`create-app.js:51`) must not leak SMTP creds.
- **Notes** N1 one Windows login per person (approval checklist) · N2 attestation none; AAGUID hint only · N3 alert on untrustedForwarded; Traefik IP check in deploy checklist · N4 /api/health returns only {ok} on the bridge listener · N5 CSRF/CORS sound; pre-auth/enrol cookies `__Host-` SameSite=Strict; new token at sign-in · N6 audit every enrolment/approval/block/recovery/failure + daily digest · N7 pin @simplewebauthn; nodemailer fine · N8 brute force negligible with S1 + S7.
- **Verified clean:** cookie flags + Origin check (`middleware.js:4-26`); trusted proxy only 172.18.0.3 (`create-app.js:16-26`); no wildcard bind (`listen.js:11`); hashed session tokens (`sessions.js:9`); equal-time password login (`auth.js:14,42-43`); unique active emails (`006:86`); CSP no inline scripts.

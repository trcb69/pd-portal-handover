# V8: do child documents bump the sales order's last_modified_time? (SPS Zoho Inventory, 8 Oct 2026)

Read-only. 136 GET calls via itexe@ CDP :9335. Raw: list.json, d.json (36 SO details), p.json (46 packages), sh.json (36 shipments), inv.json (14 invoices), analysis.json, an.js (script).

Sample: 36 SOs created since 24 Sep with shipped_status not pending, spread across the last 14 days. 46 packages, 45 package-to-shipment links (36 distinct shipments), 14 invoices.

## Verdict (SO.last_modified_time minus child time)
| Child | n | SO at/after child | SO before child | Notes |
|---|---|---|---|---|
| Package (last_modified) | 46 | 46 | 0 | 30 within 60 s, median lag 6 s |
| Shipment (last_modified) | 45 | 45 | 0 | 30 exactly equal to SO time, same second |
| Invoice (created_time) | 14 | 14 | 0 | 13 exactly equal |
| Invoice (last_modified) | 14 | 1 | 13 | invoice edited 5-24 s after creation, SO not bumped |

Package and shipment create/change bump the SO (shipping a package: package lm 16:49:31, shipment lm 16:49:36, SO lm 16:49:36). Invoice creation bumps the SO; a later edit of the invoice (13/13 saw a few seconds' follow-up edit) did not. Caveat: SO times older than the child by hours exist (max lag 5 days) only because SOs were later changed again; there is never a case of SO earlier than a package or shipment. Delete/void events and package edits long after creation were not tested.

## SO list endpoint
- `sort_column=last_modified_time&sort_order=D` works (page_context echoes it). Invalid column returns 400 code 2.
- `last_modified_time=2026-10-08T17:00:00+0530` is accepted and filters (>=): 2 rows returned vs 5 requested without it. Combine with sort_column=last_modified_time (default sort stays created_time otherwise).
- List rows carry last_modified_time, shipped_status, quantity_packed/quantity_shipped.

## Polling implication
One SO delta poll (`salesorders?last_modified_time=<watermark>&sort_column=last_modified_time&sort_order=D`) catches package and shipment changes, so no separate package or shipment list poll is needed; fetch SO detail (has packages with shipment status) only for changed SOs. Invoice creation is caught too; invoice later edits are not (irrelevant unless invoice status is shown). Keep a periodic full reconciliation for deletions.
